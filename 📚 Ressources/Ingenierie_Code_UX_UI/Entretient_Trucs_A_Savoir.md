2. Maîtrise totale de tes propres projetsAvant tout : sois capable d'expliquer CHAQUE choix technique de BMS App, Law Clean Center ou du Portfolio. Pourquoi Firebase Firestore et pas Supabase pour BMS ? Comment fonctionne l'auth ? Que se passe-t-il si la connexion Firestore tombe ? C'est la première chose qu'un recruteur va creuser, et c'est celle où tu as le plus de contrôle.

3. Consolider les fondamentaux JS/TypeScript
   
   Consolider les fondamentaux JS/TypeScriptClosures, async/await vs promesses, différence entre let/const/var, typage strict vs any, la boucle d'événements (event loop). C'est souvent l'angle mort classique des devs rapides et pragmatiques : on utilise ces concepts sans pouvoir les expliquer à l'oral.

4. Bases réseau et HTTP
   
   Bases réseau et HTTPDifférence entre GET/POST/PUT/DELETE, codes de statut HTTP (200, 401, 404, 500), ce qu'est une API REST, comment fonctionne une requête client-serveur. Chez un opérateur télécom comme Yas, ces bases comptent double — ça montre une culture technique qui dépasse le simple 'je sais coder'.

5. Structures de données et logique de base
   
   Structures de données et logique de basePas besoin de LeetCode hardcore. Sois à l'aise avec : boucles, tableaux vs objets, tri simple, complexité en gros (pourquoi une boucle imbriquée est plus lente). Les recruteurs juniors testent souvent avec un exercice simple sur tableau/chaîne de caractères.

6. Transformer ta vraie force en histoire racontable
   
   Transformer ta vraie force en histoire racontableTon point fort — trouver vite des solutions — doit devenir une anecdote structurée (situation, blocage, action, résultat). Ex: 'Sur Stockly, il fallait garantir l'encaissement même hors-ligne, j'ai dû trouver comment synchroniser SQLite avec Supabase sans conflit de données.' Ça vaut mieux qu'un aveu vague de manque de maîtrise.
